# CLI reference

Generated by `tools/gen_reference.py` from the argument parser.
Global options go **before** the command: `memory-fabric --db store.db --json overview`.

## Global options

- `--version`: show program's version number and exit
- `--db`: path to the store (default: memory.db)
- `--estimator`: value estimator for display: naive_usage (default) or ips
- `--json`: emit JSON instead of tables
- `--share-policy`: when a memory may leave this store: value (needs value evidence from verified outcomes; the default) or reviewed (once validated and active). Restricted memories never leave either way (default: $MEMORY_FABRIC_SHARE_POLICY or value)
- `--log-format`: diagnostic log format on stderr; json is one object per line (default: $MEMORY_FABRIC_LOG_FORMAT or text)
- `--log-level`: diagnostic log level (default: $MEMORY_FABRIC_LOG_LEVEL or WARNING)
- `--keys`: directory holding this store's content keys, when they are kept outside the database (default: $MEMORY_FABRIC_KEYS). Without it a store whose keys are external cannot be opened at all — which is the correct refusal, not a bug. `migrate-keys` moves an existing store's keys out.
- `--create`: create the store if it does not exist (otherwise a missing path is an error)

## Commands

### `access-log-verify`

Check the dashboard access log's hash chain (exit 0 intact, 5 broken)

- `path`: the access log file (JSON lines)

### `agent-api`

WRITES: serve agents over authenticated HTTP (recall, fetch, verify, remember), each request verified from a signed, expiring credential

- `--agents-file`: agent_id:tenant_id:hex_key per line; secret, server-only
- `--host`: address to bind (default loopback)
- `--port`: TCP port to listen on
- `--behind-tls`: allow a non-loopback bind because TLS terminates in front
- `--rate-limit`: requests a second per agent, on average (0 turns it off)
- `--burst`: requests per agent at once
- `--no-maintain`: do not run the background memory manager in this process
- `--maintain-interval`: seconds between background maintenance cycles
- `--peers`: JSON peer list for retraction delivery (or $MEMORY_FABRIC_PEERS)
- `--checkpoint-dir`: write integrity checkpoints here, off the store's disk (or $MEMORY_FABRIC_CHECKPOINT_DIR)
- `--retention-delete`: let the manager apply retention deletions (terminal); off by default

### `agent-api-issue`

Print a signed, expiring credential for one agent

- `--agents-file`: agent_id:tenant_id:hex_key per line; secret, server-only
- `--agent`: the agent to issue a credential for
- `--ttl`: lifetime in seconds

### `agent-api-revoke`

WRITES: revoke a leaked credential, or all of one agent's; a running agent-api on this store refuses it on the next request

- `--agents-file`: agent_id:tenant_id:hex_key per line; secret, server-only
- `--agent`: revoke every credential this agent holds
- `--token`: the leaked credential, or - to read it from stdin

### `anchor`

Anchor the integrity checkpoint off the store (dir:, git:, https://), or verify anchors

- `--to`: dir:PATH, git:REPO or an http(s) URL; repeat for several
- `--verify`: an anchors file or dir: directory to check this store against

### `attention`

Triage list: what needs a human, worst first

- `--severity`: show only items at or above this severity

### `audit`

Every logged event that touched one memory

- `id`: the memory id

### `audit-export`

Export decisions, changes, access events and deletion receipts as JSONL, without memory content, ending with a hash-chain checkpoint

- `--out`: file to write (JSON lines, content-free)
- `--kind`: which records to include; repeatable (default: all)
- `--since-seq`: only events after this log sequence

### `backup`

Consistent snapshot of the event log, verified by replaying it

- `path`: where to write the copy
- `--force`: overwrite an existing file
- `--with-keys`: also copy the key directory named by --keys, beside the copy (<path>.keys/). Keep that copy as protected as the original
- `--include`: a config file or directory to keep with the backup (<path>.config/): agents.txt, a peers file, a checkpoint directory. Repeatable

### `branch`

Memory branches: list, show, diff, or WRITES: create, add, revise, withdraw (each a one-change commit), close

- `action`: list, show (history), diff; or create, add, revise, withdraw, close
- `name`: the branch
- `--actor`: who is acting; the owner for create and close
- `--text`: the memory text to add or the revised text
- `--memory`: the main memory to revise or withdraw
- `--reason`: why it is withdrawn
- `--message`: the commit message
- `--member`: repeatable: an agent who may write to the branch
- `--reviewer`: repeatable: an agent who may merge it into main
- `--tenant`: tenant id to act within

### `checkpoint`

Print an integrity checkpoint, or verify against a saved one

- `--verify`: a checkpoint JSON file saved earlier, elsewhere

### `collection`

Collections: named sets of memories agents can be attached to. list, or WRITES: add/remove a memory, attach/detach an agent, grant/revoke permissions

- `action`: what to do with the collection
- `name`: the collection's name
- `--memory`: memory id to add or remove
- `--agent`: agent to grant or revoke
- `--permission`: repeatable; attach means read
- `--actor`: who is changing this; required for a change
- `--tenant`: tenant id to act within

### `context`

Build an agent's context bundle under a token budget and record its receipt (WRITES the receipt), list receipts, or explain one

- `action`: build a bundle and its receipt, list receipts, explain one; wake/zoom the decay view, list nodes pending a summary, summarise one
- `receipt`: a receipt id, for explain
- `--agent`: the agent the context is for
- `--query`: what the agent is working on (stored only as a digest)
- `--budget`: token budget (estimated as characters / 4)
- `--mode`: auto picks exact for numbers, ids and dates, else balanced
- `--limit`: how many receipts to list
- `--node`: a decay-view node LO-HI, for zoom and summarise
- `--text`: the summary to store for --node (summarise)
- `--tenant`: tenant id to act within

### `correct`

Preview what withdrawing a memory would touch; with --apply, WRITES it and owes the retraction to every store that received it

- `id`: the memory id
- `--apply`: withdraw it and owe retractions (without this, only preview)
- `--status`: what each store acknowledged
- `--reason`: why, recorded with the change
- `--actor`: who is correcting this; required with --apply
- `--basis`: the evidence for withdrawing it (contradicted, sensitive_data, ...)
- `--preview`: the digest the preview printed; --apply refuses if the store changed

### `demo`

WRITES: seed a demonstration store


### `doctor`

Whether this installation's answers can be believed (exit 0/1/5)

- `--webhook`: POST a JSON alert here when the store is not sound
- `--webhook-on`: alert on failures only (default), or on warnings too

### `episodes`

List episodes and their verified outcomes

- `--limit`: show at most this many episodes

### `erase`

WRITES: crypto-erase one memory's content (provenance and audit stay), then report what the erasure reached and what it could not

- `id`: the memory id
- `--reason`: recorded with the erasure, e.g. a ticket id
- `--actor`: who is making this change; recorded in the audit trail

### `erasure-scope`

What an erasure of one memory reached, kept, and could not reach

- `id`: the memory whose erasure you are scoping

### `federate`

WRITES: receive signed retractions and notices from peers over HTTP, and deliver this store's to them (the background manager)

- `--peers`: JSON peer list: who this store talks to (or $MEMORY_FABRIC_PEERS)
- `--host`: address to bind (default loopback)
- `--port`: TCP port to listen on
- `--behind-tls`: allow a non-loopback bind because TLS terminates in front
- `--allow-plain-http`: allow a non-loopback bind over plain HTTP on a private network; messages are signed, not encrypted
- `--no-maintain`: receive only; do not deliver this store's retractions
- `--maintain-interval`: seconds between background maintenance cycles
- `--checkpoint-dir`: write integrity checkpoints here, off the store's disk (or $MEMORY_FABRIC_CHECKPOINT_DIR)
- `--retention-delete`: let the manager apply retention deletions (terminal); off by default

### `forget`

WRITES: deprecate a memory

- `id`: the memory id
- `--actor`: who is making this change; recorded in the audit trail
- `--reason`: why, recorded with the change

### `import`

WRITES: import another store's export (JSON list or JSONL: Mem0, LangChain documents, plain content) as private candidates waiting for review

- `file`: a text, Markdown or JSONL file to import as memories
- `--source`: where it came from, recorded on each memory
- `--agent`: author for records that do not name one
- `--tenant`: tenant id to act within

### `incident`

Guided incident response: list candidates, assess one, --contain it (WRITES), --record FILE a reviewable record

- `id`: the memory at the centre of the incident; omit to list candidates
- `--contain`: withdraw it, contest what rests on it, and owe retractions to peers
- `--record`: .md (default) or .json
- `--verify`: check containment from the store's state: exit 0 contained, 1 contained with actions to review, 3 unresolved
- `--reason`: why, recorded with the change
- `--actor`: who is making this change; recorded in the audit trail

### `init`

Set up a store the way production should run it, in one step.

A directory with the store, its content keys kept *outside* the database
(the production default: a copy of the `.db` alone reads nothing), and an
agents file with one agent and a fresh signing key, owner-only. Prints the
MCP client configuration and the next commands, then runs `doctor`. It
never overwrites: an existing store is an error, not a reset.

- `dir`: directory to create the store in
- `--agent`: the first agent to register
- `--tenant`: its tenant id

### `lifecycle`

Retention rules, stale and sensitive memories, and erasure and retraction progress across stores. Read-only

- `--stale-days`: memories unused for this many days count as stale
- `--limit`: show at most this many

### `lineage`

Derivation tree in either direction

- `id`: the memory id
- `--direction`: ancestors (what it came from), descendants (what came from it), or both
- `--depth`: how many generations to follow

### `list`

List memories

- `--state`: filter by lifecycle state (candidate, active, contested, ...)
- `--scope`: filter by scope (private, team, federated)
- `--tenant`: only memories belonging to this tenant
- `--agent`: only memories this agent wrote (from provenance)
- `--type`: filter by memory type (semantic, episodic, procedural, ...)
- `-q, --query`: substring of content or id
- `--limit`: show at most this many
- `--sort`: sort order

### `maintain`

Run the background memory manager (also started by serve, mcp and agent-api)

- `--once`: one cycle, then exit
- `--status`: the last cycle, and what it found that needs a person
- `--no-maintain`: do not run the background memory manager in this process
- `--maintain-interval`: seconds between background maintenance cycles
- `--peers`: JSON peer list for retraction delivery (or $MEMORY_FABRIC_PEERS)
- `--checkpoint-dir`: write integrity checkpoints here, off the store's disk (or $MEMORY_FABRIC_CHECKPOINT_DIR)
- `--retention-delete`: let the manager apply retention deletions (terminal); off by default

### `mcp`

WRITES: serve this store to one agent over MCP (stdio). The agent can recall, fetch, verify and remember; it cannot record outcomes or see withdrawn memories

- `--agent`: the agent id every call is attributed to
- `--tenant`: tenant (default tn_default)
- `--trusted-local`: the agent's clean writes become active without review (marked in provenance). For one person's local assistant only.
- `--extended-tools`: also offer build_context, explain_context, trace_provenance, preview_correction, branch_create, branch_propose and merge_preview. None applies a merge or a correction.
- `--no-maintain`: do not run the background memory manager in this process
- `--maintain-interval`: seconds between background maintenance cycles
- `--peers`: JSON peer list for retraction delivery (or $MEMORY_FABRIC_PEERS)
- `--checkpoint-dir`: write integrity checkpoints here, off the store's disk (or $MEMORY_FABRIC_CHECKPOINT_DIR)
- `--retention-delete`: let the manager apply retention deletions (terminal); off by default

### `merge`

Preview merging a branch into main; WRITES with apply (needs the preview's digest and an idempotency key), or revert a merge

- `action`: preview, apply (needs --preview and --key) or revert (a merge id)
- `name`: the branch (or, for revert, the merge id)
- `--actor`: who is merging (the owner or a reviewer); audited
- `--preview`: the full digest the preview printed
- `--key`: an idempotency key: a retry with it replays, never applies twice
- `--tenant`: tenant id to act within

### `migrate-keys`

WRITES: move content keys out of the database into a directory, verified by replay before anything is removed

- `directory`: where the keys will live from now on

### `offer`

WRITES: offer one memory to a peer store over HTTP. It lands there as a candidate, recorded as from this store; a correction here follows it

- `id`: the memory to offer
- `--to`: the peer's store id, as in the peers file
- `--peers`: JSON peer list (or $MEMORY_FABRIC_PEERS)
- `--actor`: who is sharing it; recorded here

### `overview`

Store health and what it can and cannot tell you


### `posture`

Which security controls are on in this store, and the accepted gaps


### `quarantine`

WRITES: quarantine a memory and contest its descendants. Quarantine on evidence about the memory, not on it having been in context at a failure - that policy makes an agent much worse.

- `id`: the memory id
- `--reason`: why, recorded with the change
- `--actor`: who is making this change; recorded in the audit trail
- `--basis`: what kind of evidence this rests on. Omitted is recorded as 'unstated', which the attention list then flags - as it does 'co_occurrence', because being present when something failed is agreement, not causation.
- `--no-propagate`: leave descendants alone (they keep a retracted justification)

### `receipt-verify`

Verify a signed action receipt (exit 0 valid, 5 invalid); needs no store

- `path`: the receipt JSON file
- `--public-key`: the signer's Ed25519 public key, base64, obtained independently

### `release`

WRITES: return a quarantined memory to candidate

- `id`: the memory id
- `--actor`: who is making this change; recorded in the audit trail
- `--reason`: why, recorded with the change

### `restore`

WRITES: restore a backup made with `backup`, after checking its manifest

- `backup`: the backup file (its .manifest.json must be beside it)
- `dest`: directory to restore into; must not exist

### `retention`

Preview retention; --apply to act on it

- `--apply`: WRITES: apply the decisions

### `review`

The review queue. With an id and a decision, WRITES it: approve (usable by the team), limit (usable by its author only), correct, or reject

- `id`: the candidate to decide on; omit to list the queue
- `--approve`: make it active
- `--limit`: show at most this many
- `--reject`: quarantine it
- `--correct`: replace its content with a corrected version
- `--reason`: why, recorded with the change
- `--actor`: the reviewer; required for a decision
- `--override-screen`: approve a memory an ingest screen quarantined
- `--tenant`: only this tenant's queue

### `sandbox`

A throwaway store with deliberately wrong memories, opened in the dashboard

- `--port`: TCP port to listen on
- `--dir`: where to create it (default: a new temporary folder)
- `--no-serve`: seed only; print the path

### `search`

Search the index without logging anything

- `query`: text to search for
- `--limit`: show at most this many
- `--retrievable`: only states an agent could actually receive

### `serve`

Start the read-only web dashboard

- `--host`: bind address (default 127.0.0.1). Anything else needs authentication.
- `--port`: TCP port to listen on
- `--quiet`: do not log requests
- `--token`: fixed session token; a random one is generated if omitted. Also read from $MEMORY_FABRIC_TOKEN, which keeps it out of the process list.
- `--no-auth`: serve without authentication; refused unless bound to loopback
- `--allowed-host`: extra Host header value to accept; repeatable. Needed when reaching the server by a name or address other than localhost.
- `--operators-file`: one 'name:token' per line, so each operator has their own token and every request is attributable. Tokens are never printed.
- `--access-log`: append who looked at what, one JSON line per request (default with --operators-file: <db>.access.jsonl; '-' turns it off)
- `--no-maintain`: do not run the background memory manager in this process
- `--maintain-interval`: seconds between background maintenance cycles
- `--peers`: JSON peer list for retraction delivery (or $MEMORY_FABRIC_PEERS)
- `--checkpoint-dir`: write integrity checkpoints here, off the store's disk (or $MEMORY_FABRIC_CHECKPOINT_DIR)
- `--retention-delete`: let the manager apply retention deletions (terminal); off by default

### `share`

WRITES: widen who may read a memory (private -> team -> federated), through the firewall, logged

- `id`: the memory to share
- `--scope`: how far it may travel: team or federated
- `--actor`: who is deciding this
- `--all-private-active`: share every active private memory: the upgrade path for stores written before scope was enforced on reads

### `show`

Why the system remembers one memory

- `id`: the memory id

### `suspicious`

Memories whose claim contradicts what the store knows: a corrected value restated, a value far out of range, or a contradiction of an established fact

- `--limit`: show at most this many

### `tenants`

Which tenants this store holds


### `tour`

The whole idea in sixty seconds: one fact, four agents, one correction

- `--fast`: print it at once, without pauses

### `validate`

WRITES: promote a candidate to active

- `id`: the memory id
- `--actor`: who is making this change; recorded in the audit trail
- `--reason`: why, recorded with the change

# P1c — prefer the chain whose weakest link is strongest

Registered in [p1c-link-strength.md](../prereg/p1c-link-strength.md)
before the change. Produced by `python -m experiments.p1c_strength` at commit
`97c0000`; raw numbers in [p1c-strength.json](p1c-strength.json).

**NOT SUPPORTED.** On the fresh holdout, the chain's sufficiency goes from
0.250 to 0.458 against an oracle ceiling of 1.000
(threshold 0.550; 28% of the headroom closed). Dev not
worse: True. Arms above the ceiling: none.

The **test** row is not evidence. P1 inspected a case there and saw the
failure this change targets, so the change was designed with that split in
view. It is printed so the reader can see it was not hidden.

**What it does not establish.** The holdout is generated by the same templates
as dev and test, so it is new cases, not a new distribution. Only the chain
families are measured. `reconstruct` remains opt-in either way; `retrieve` is
the default and is unchanged.

**Holdout 1 (contaminated: P1c was diagnosed on it).** Before 0.167, after 0.458.

## Reading

**NOT SUPPORTED as registered: 28% of the headroom against 40%.** The change
is kept off (`chains.LINK_STRENGTH_SELECTION = False`), as the registration
required.

It is still the first change to the chain search that improves a fresh
holdout. Secondary, not gating, `multi_hop_3` alone:

| split | before | after |
|---|---|---|
| dev | 0.667 | 1.000 |
| holdout | 0.500 | 0.917 |
| holdout1 | 0.333 | 0.917 |
| test | 0.667 | 1.000 |

`multi_hop_4` stays at 0.000 under any chain-selection change, because it also
needs a modifier the search never reaches (P1). The registration said in
advance that pooling would dilute the effect, and set the threshold on the
pooled metric anyway. Re-cutting to `multi_hop_3` now would be choosing the
metric after seeing it.

Cost: nodes explored are unchanged, because only goal selection changed.

**What would justify turning it on:** a registration on a third fresh holdout,
with `multi_hop_3` as the primary metric declared in advance. Holdout 2 is now
spent for that purpose too, because the per-family split above was read from it.
